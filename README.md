# WarpScout

Android-приложение для работы через Cloudflare WARP: находит рабочий сервер в вашей сети, само
поднимает туннель WireGuard/AmneziaWG, показывает, что реально открывается, и позволяет отправлять
часть трафика в собственную страну через второй туннель.

Проект не аффилирован с Cloudflare. Это клиент, который сам реализует протокол: handshake, обмен
ключами, сессии, пересогласование и разбор пакетов. Никаких сторонних VPN-библиотек и никакого
сервера-посредника — только endpoint'ы Cloudflare и ваш телефон.

---

## Возможности

**Подбор сервера**
- Скан пула Cloudflare: подсети × порты, до 1 500 точек, параллельно 64 сокета.
- Каждый профиль шума проверяется на каждой из лучших точек — не угадывается, а сравнивается:
  `none` (чистый WireGuard), `tls-fixed`, `quic:` под три SNI, `sip`.
- Топ-кандидаты поднимаются настоящим туннелем, и по ним прогоняются проверки сайтов (Google,
  YouTube, ChatGPT, Telegram, Discord, X и другие).
- Победитель выбирается по числу реально открывшихся сайтов и только потом по скорости и
  стабильности. Результат попадает в конфиг и используется при подключении.

**Туннель**
- Собственный VpnService: handshake, transport-пакеты, keepalive, пересогласование сессии каждые
  120 секунд.
- Перебор точек входа: до пяти разных пар «адрес:порт», ротация между подключениями.
- Переподключение после смены сети (Wi-Fi ↔ мобильные) без участия пользователя.
- Обнаружение мёртвой сессии: если пересогласование не проходит дважды подряд, туннель
  переподнимается, а не висит «зелёным».
- Ограничение автопереподключений (не больше шести за десять минут), чтобы мёртвая сеть не
  превращалась в бесконечный цикл и не съедала батарею.

**Второй выход: регион для отдельных сайтов**
- WARP — anycast, страну выхода выбрать нельзя. Поэтому регион задаётся вторым туннелем к своему
  WireGuard/AmneziaWG-серверу.
- Домены разворачиваются в адреса через DoH и попадают в таблицу маршрутизации; всё остальное идёт
  через WARP.
- Если второй сервер недоступен, его подсети возвращаются в WARP: сайт работает, регион другой,
  туннель не рвётся.

**Разделение по приложениям**
- «Всё через туннель», «только выбранные», «всё, кроме выбранных» — как в Amnezia.

**Разделение по адресам**
- Весь трафик, встроенные списки, списки allow-domains или свои CIDR. Списки обновляются из
  источника и собираются в маршруты.

**Диагностика**
- Постоянный статус соединения: работает / выключено / подключаюсь / ошибка с причиной.
- Журнал каждого шага с временем и длительностью этапа.
- Проверка, что открывается через текущий туннель.
- Запись падений: если приложение всё-таки упало, стектрейс сохраняется и показывается при
  следующем запуске.
- Пояснения на человеческом языке: почему не поднялось и что попробовать.

**Данные и приватность**
- Резервные копии настроек и последнего рабочего конфига — автоматически после подключения, плюс
  вручную.
- Экспорт в `.conf` для Amnezia/WireGuard, в Clash YAML и только маршрутами, плюс буфер обмена.
- Аккаунт Cloudflare WARP генерируется на телефоне. Ключи не покидают устройство.
- Приложение не собирает телеметрию и не отправляет ничего, кроме запросов к endpoint'ам Cloudflare
  и DoH-запросов при разрешении доменов второго выхода.

## Установка

Готовые APK — в разделе [Releases](../../releases). Две сборки:

| Сборка | Что делает | Application ID |
|---|---|---|
| `WarpScout-<версия>-tunnel.apk` | Полная: подбор + собственный туннель | `dev.warpscout.app.tunnel` |
| `WarpScout-<версия>-scout.apk` | Только подбор и экспорт конфигов (для AmneziaVPN) | `dev.warpscout.app` |

Обе можно держать на телефоне одновременно: идентификаторы различаются.

Требования: Android 8.0 и новее. Для разделения по приложениям и расхода по приложениям система
может запросить дополнительные разрешения — приложение объясняет, зачем они.

Установка APK из файла: разрешите «Установка неизвестных приложений» для файлового менеджера или
браузера, которым открываете файл.

## Быстрый старт

1. Откройте вкладку **Главная** и нажмите **«Сканировать и подобрать»**. Подбор занимает несколько
   минут: сначала быстрый скан, потом проверка топ-точек со всеми профилями шума и проверка сайтов
   из-под туннеля. На той же сети следующая попытка начинается иначе: недавняя рабочая точка
   проверяется первой (секунды вместо минут), а полный скан запускается, только если она перестала
   работать. Подбор идёт в foreground-сервисе, поэтому его можно свернуть, не оборвав.
2. Нажмите **«Включить туннель»**. Приложение поднимает туннель подобранной конфигурацией и
   запоминает её: следующее подключение идёт той же конфигурацией, подбор не нужен.
3. Проверьте на вкладке **Диагностика**, что открывается. Если что-то не открылось — там же будет
   объяснение, что именно мешает.

Дальше можно ничего не трогать: подключение одним касанием, при смене сети туннель переподключается
сам.

## Вкладки

**Главная** — статус соединения, последний подбор, три кнопки (подобрать, подключить, настройки),
резервные копии.

**Подбор** — что именно сканировать: пул адресов или свои подсети, порты, период фонового подбора,
профили шума, которые участвуют в сравнении, проверки ресурсов.

**Настройки** — всё, что попадает в конфиг и в туннель: сервер и профиль шума (или «авто»), DNS,
MTU, keepalive, IPv6, разделение по адресам и спискам, второй выход, формат экспорта, экспорт и
импорт, резервные копии.

Важно: настройки не применяются сами. На каждом экране есть **«Сохранить»** (только сохранить) и
**«Сохранить и применить»** (сохранить и переподключить туннель). Так изменение на лету не рвёт
рабочее соединение.

**Приложения** — что пускать через туннель: всё, только выбранные, всё кроме выбранных. Список
приложений с поиском; при наличии разрешения — расход по приложениям.

**Диагностика** — журнал этапов, проверка ресурсов, отчёт последнего подбора, копирование журнала
(включая записанные падения) и версия сборки.

## Второй выход: регион для отдельных сайтов

WARP — anycast: узел выбирает Cloudflare по вашей сети, выбрать страну нельзя. Если нужен конкретный
регион для конкретных сайтов, нужен свой сервер.

1. Поднимите WireGuard или AmneziaWG на любом VPS в нужной стране (пятиминутная задача, ставится
   пакетом `wireguard`).
2. В приложении: **Настройки → Второй выход (регион)**. Вставьте клиентский конфиг
   (`[Interface]` / `[Peer]`), перечислите домены.
3. Нажмите **«Собрать IP из доменов»** — домены развернутся в адреса через DoH (`/32` и `/128`).
4. **«Сохранить и применить»**.

Пакеты на эти адреса пойдут через ваш сервер, всё остальное — через WARP. Если сервер недоступен,
подсети автоматически вернутся в WARP.

Ограничения: сайты на общих CDN-адресах могут уйти не через тот выход; для Outline/Shadowsocks
второй выход не подходит (им нужен TCP-стек).

## Настройки, которые чаще всего меняют

| Настройка | Значение по умолчанию | Когда менять |
|---|---|---|
| Профиль шума | авто (из подбора) | если на новой сети не подключается — попробовать `tls-fixed` или `none` |
| MTU | 1280 | если сайты открываются частично: 1280 стабильнее 1420 |
| Keepalive | 25 с | `0` — экономнее батарею, но NAT может быстрее забыть соединение |
| IPv6 | включён | отключить, если «туннель есть, интернета нет» |
| Режим маршрутов | весь трафик | «по спискам», если нужен только нужный трафик в туннеле |
| Период фонового подбора | выключен | 6–12 часов; при поднятом туннеле подбор откладывается |

## Если не подключается

Приложение пишет причину в **Диагностику** человеческим языком. Самые частые случаи:

**«сервер молчит: N инициаций без ответа»** — сеть не пропускает handshake. Что делать по порядку:
сменить профиль шума (`tls-fixed`, затем `none`), сменить порт, отключить IPv6, попробовать другую
сеть (Wi-Fi ↔ мобильные). Подбор перебирает пять разных точек входа автоматически.

**«туннель поднялся, но трафик не идёт»** — обычно IPv6 в сети без поддержки IPv6 в туннеле:
отключите IPv6 и переподключитесь. Второй подозреваемый — MTU.

**«подключено, но сайты не открываются»** — пересогласование сессии не проходит, приложение это
заметит и переподнимет туннель. Если повторяется — смените точку входа.

**«нет сети — жду подключения»** — сеть пропала; как только она появится, туннель поднимется сам.
Если сети нет 45 секунд, туннель снимается, чтобы трафик не уходил в пустоту.

**«автопереподключение приостановлено»** — сеть стабильно не пропускает WARP: больше шести попыток
за десять минут бессмысленны. Нажмите «Подключить» вручную или смените профиль шума.

**Разрешение VPN не выдано** — Android спрашивает подтверждение при первом подключении. Если
отказали, включите заново: приложение показывает инструкцию.

## Батарея

| Состояние | Расход |
|---|---|
| Приложение закрыто, туннель выключен | практически ноль: нет wakelock, нет alarm'ов, фоновый подбор по умолчанию выключен |
| Туннель поднят, экран погашен | Wi-Fi — меньше 1 %/час, мобильная сеть — 1–3 %/час: keepalive раз в 90 секунд вместо 25, пересогласование раз в 150 вместо 120 |
| Туннель поднят, телефон в работе | keepalive раз в минуту: пока экран горит и трафик идёт, лишний пакет дешевле задержки |
| Туннель поднят, телефон в работе | меньше, чем расходует сам экран и трафик |
| Подбор конфигурации | обычный скан — единицы процентов, «полный перебор» — десятки: минуты непрерывной работы радио. Повторный подбор на той же сети почти бесплатен: проверяется одна сохранённая точка |

На мобильной сети расход выше, чем на Wi-Fi: пробуждение радиомодуля дороже самого пакета.
Поэтому интервал keepalive зависит от состояния: экран погашен и трафика нет — реже, экран горит —
чаще. В журнале (`Диагностика`) раз в полчаса появляется строка `статистика: …` — сколько было
пробуждений, рукопожатий и сколько секунд без трафика: по ней видно, что именно расходует батарею.

## Сборка из исходников

```bash
git clone https://github.com/kos19191/warp-scout-src
cd warp-scout-src

./gradlew :app:assembleTunnelDebug      # полная сборка
./gradlew :app:assembleScoutDebug       # только подбор
./gradlew :core:check                   # самопроверка протокольного слоя
```

Требуется JDK 17 и Android SDK (compileSdk 35). Подпись релиза — через `app/release.keystore` и
переменные окружения `WARPSCOUT_STOREPASS`, `WARPSCOUT_KEYALIAS`, `WARPSCOUT_KEYPASS`; без них
используется debug-ключ.

Структура:

```
core/   протокольный слой: WireGuard/AmneziaWG, криптография, подбор, маршруты, списки
app/    Android-приложение: экраны, VpnService, настройки, экспорт
cli/    консольный вариант подбора (без Android)
tools/  оффлайн-проверка разметки и ресурсов для CI
```

CLI:

```bash
./gradlew :cli:installDist
./build/install/cli/bin/cli tune --profiles 4 --count 200
```

## Проверки

- `tools/android_stub_check.py` — оффлайн-проверка ресурсов, разметки и типов полей без SDK:
  висячие ссылки, дубликаты id, вложенность `ScrollView`, соответствие `findViewById` типам.
- Самопроверка протокольного слоя (`SelfCheck`) — криптография, handshake, разбор конфигов,
  маршрутизация, таблицы адресов.
- CI (`.github/workflows/android.yml`) собирает обе сборки и прогоняет самопроверку на каждый коммит.
