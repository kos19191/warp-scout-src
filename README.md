# WarpScout

Android-приложение для работы через Cloudflare WARP. Оно само находит в вашей сети адрес
Cloudflare, который пропускает трафик, поднимает на нём туннель и держит его: переподключается
после обрыва и смены сети, меняет точку входа, когда прежняя перестала отвечать, и показывает, что
реально открывается. Сайты, закрытые для российских адресов (ChatGPT, Claude, Gemini, Grok), оно
может пускать через второй выход — ваш сервер WireGuard/AmneziaWG или бесплатный Proton VPN.

Проект не аффилирован с Cloudflare. Протокол реализован в самом приложении — обмен ключами,
handshake, сессии, пересогласование, разбор пакетов, маршрутизация, — без сторонних VPN-библиотек
и без сервера-посредника.

## Установка и обновление

Готовые APK — в разделе [Releases](../../releases); там хранятся пять последних версий. В каждом
релизе три файла:

| Файл | Что внутри | Application ID |
|---|---|---|
| `WarpScout-<версия>-tunnel.apk` | открывается упрощённым экраном: кнопка, связь, резервная точка | `dev.warpscout.app.tunnel` |
| `WarpScout-<версия>-scout.apk` | то же приложение, открывается расширенным экраном со всеми вкладками | `dev.warpscout.app` |
| `SHA256SUMS.txt` | контрольные суммы SHA-256 обоих APK | |

Сборки различаются только видом экрана при первом запуске; вид меняется тумблером внизу экрана и
запоминается. Обе можно держать на телефоне одновременно (VPN в Android при этом работает только
один). Сборки подписаны debug-ключом: для установки из файла, не для магазина приложений.

**Требования.** Android 8.0 и новее. При первом подключении система спросит разрешение на VPN, на
Android 13 и новее — ещё на уведомления (уведомление туннеля и вопрос про Telegram). Других
разрешений нет: в списке для «только выбранные / всё кроме выбранных» — приложения с иконкой на
рабочем столе, доступ ко всему списку пакетов не нужен. Разрешения «Установка приложений» у
WarpScout тоже нет: ставить другие приложения оно не может (антивирусы, в том числе «Защита
приложений» Samsung, считают такое разрешение признаком «загрузчика»).

**Установка.** Разрешите «Установка неизвестных приложений» браузеру или файловому менеджеру,
которым открываете APK, и откройте файл.

**Обновление.** Кнопка «Проверить обновления» (в расширенном виде — внизу «Главной», в упрощённом —
значок в шапке) смотрит последний релиз на GitHub. Есть новая версия или свежая сборка той
же — предлагает скачать. Файл ложится в «Загрузки»; поставить — нажатием на него или на уведомление
«Загрузка завершена», поверх: настройки, ключи и подобранный конфиг сохраняются.

- Качает системная загрузка Android. Если она полминуты не получила ни байта (ждёт сеть, повторяет
  попытку, стоит в очереди) или 45 секунд не продвигается, приложение убирает её и качает файл само,
  тоже в «Загрузки»: сначала через туннель, не вышло — мимо него. Файл сверяется с
  `SHA256SUMS.txt`. Не вышло и так — приложение называет причину и предлагает скачать браузером.
- Повторное нажатие говорит, что именно происходит: «системная загрузка ждёт сеть — через 20 с
  скачаю сам», проценты, — а в журнале остаются статус и причина.
- При раздельных маршрутах («сайты из списков», «мои сайты», браузер — только к нужным сайтам) сети
  GitHub идут через туннель: напрямую GitHub у российских операторов бывает недоступен.
- На Android 8–9 системной загрузке нужно разрешение на запись в память — там файл качает браузер.

Вернуться на более старую версию можно только через удаление: поверх новой Android старую не
ставит, а при удалении сотрутся настройки — перед этим сохраните резервную копию.

**Резервная копия.** Один файл со всем, что помнит приложение: настройки и рабочий конфиг, тройки
точек для Wi-Fi и мобильной сети (из них выбирается резервная точка), второй выход, приложения и
сайты в туннеле, выход по приложениям, память точек, площадок и ответов про Telegram, кеш подбора,
конфиг для автоподъёма, скачанные списки сайтов, серверы Proton Free и ключ аккаунта WARP. До 1.10.43.1
в копию попадали только основные настройки — тройки точек, память, списки и ключ аккаунта после
восстановления пропадали.

- Приложение само пишет копию после каждого подключения и подбора, но хранит у себя (десять последних):
  при удалении приложения они стираются вместе с ним.
- Кнопка «Сохранить резервную копию» (расширенный вид, «Главная») кладёт копию в «Загрузки/WarpScout»
  и показывает, что в ней; «Отправить…» в том же окне — на Диск или в Telegram. На Android 8–9 (и если
  запись в «Загрузки» не удалась) открывается окно «Сохранить как».
- «Восстановить из копии» предлагает последнюю копию приложения, последнюю в «Загрузках/WarpScout» и
  «Выбрать файл…» — окно выбора открывается сразу в Download/WarpScout. Копию, записанную другим
  приложением (обычным WarpScout для беты), Android без разрешений не показывает в списке — её
  открывают через «Выбрать файл…». Файл из Telegram сначала сохраните на телефон.
- Перед восстановлением видно, что в копии: число настроек, второй выход, тройки точек, списки, ключ.
  Восстановление заменяет всё, как было в копии; копия старого формата — только основные настройки.
- В копии ключи WARP и второго выхода открытым текстом (в хранилище ключей они зашифрованы ключом этого
  телефона, и в другом приложении их не прочесть) — не выкладывайте её в открытый доступ.

## Что делает приложение

- **Два вида экрана.** Упрощённый — одна большая кнопка «включить/выключить», строка «где мы»,
  проверка связи и резервная точка; расширенный — все вкладки: подбор, настройки, туннелирование,
  журнал. Переключает еле заметный тумблер внизу экрана, выбор запоминается. Тема — светлая, тёмная
  или как в системе («Настройки» → «Тема оформления»).
- **Подбирает рабочую точку входа.** Перебирает адреса и порты Cloudflare WARP, проверяет их
  настоящим handshake, а не пингом, и оставляет те, что ответили именно вашему ключу.
- **Поднимает туннель само.** Свой `VpnService`: WireGuard/AmneziaWG внутри приложения, без внешних
  библиотек. Подключение — одно нажатие, при обрыве туннель поднимается заново без вас.
- **Меняет точку, когда прежняя умерла.** Держит очередь проверенных адресов и переходит на
  следующий сам — в том числе ночью, когда никто не нажимает кнопок.
- **«Подключено» значит «данные ходят».** После подъёма, при открытии экрана и когда приложения шлют
  пакеты без ответа, сервис проверяет связь запросом через сам туннель: Cloudflare по IP (заодно
  видно, через WARP ли ушёл запрос и где выход) и TCP-соединение с сервером Telegram. Два провала
  подряд — туннель переподключается сам.
- **Говорит, где вы.** Строка под кнопкой: вид сети, точка входа, страна выхода WARP и — если второй
  выход поднят — его страна: «мобильная · вход 8.35.211.3:864 · выход RU · второй выход NL».
- **Показывает, что реально открывается.** Прогоняет список сайтов из-под туннеля и говорит
  «открылось / не открылось», а не «подключено, наверное, работает».
- **Резервная точка.** Её выбирают из лучших точек последнего подбора (у каждой видно, что о ней
  знает фоновая проверка: «отвечает» или «не ответила в 12:53»). Если текущая замолчит, туннель
  перейдёт на резервную первой. «Подключить» сначала проверяет точку рядом с работающим туннелем и
  не гасит его, если точка молчит.
- **Возвращается сам после перезагрузки и обновления** — если перед этим туннель был включён и его
  не выключали вручную. Выключенный руками (кнопка, плитка, уведомление) туннель сам не включается.
- **Второй выход.** WARP — anycast, страну выхода выбрать нельзя. Сайты, которые не работают с
  российских адресов, можно пустить через свой сервер WireGuard/AmneziaWG или Proton VPN Free.
- **Разделяет трафик.** По приложениям (всё, только выбранные, всё кроме выбранных), по сайтам и по
  выходу: приложение можно навсегда оставить на WARP или целиком пустить через второй выход.
- **Объясняет отказы по-русски.** В журнале видно каждый шаг с временем и длительностью и что
  делать, если не поднялось. «Выгрузить журнал в .txt» (вкладка «Журнал») сохраняет журнал целиком в
  «Загрузки» и сразу открывает «Поделиться»: с версией и номером сборки, телефоном, состоянием
  сервиса, последним подбором и падениями. «Скопировать журнал» кладёт в буфер обмена только хвост —
  длинный текст режут и буфер, и мессенджеры. Журнал хранит до мегабайта строк: при переполнении
  остаются последние ~640 КБ — обычно это ночь и весь следующий день.
- **Показывает, сколько туннель уже работает.** Время считается от подъёма сессии, а не от открытия
  экрана. Журнал открывается на самых свежих строках, разделы переключаются кнопками снизу или
  смахиванием влево-вправо.

## Как это работает

### 1. Подбор точки входа

Cloudflare WARP отвечает на любой из своих anycast-адресов, но в каждой сети часть адресов и
портов закрыта. Приложение перебирает их и проверяет по-настоящему.

**Что перебирается:**

- подсети Cloudflare WARP: `162.159.192.*`, `162.159.195.*`, `8.6.112.*`, `8.34.70.*`,
  `8.34.146.*`, `8.35.211.*`, `8.39.125.*`, `8.39.204.*`, `8.39.214.*`, `8.47.69.*`,
  `188.114.96.*`…`188.114.99.*`, плюс имя `engage.cloudflareclient.com`;
- октеты `1…10` внутри подсети (не весь /24: разницы в поведении нет, а скан в 25 раз короче);
- порты из документации WARP: 500, 854, 859, 864, 878, 880, 890, 891, 894, 903, 908, 928, 934,
  939, 942, 943, 945, 946, 955, 968, 987, 988, 1002, 1010, 1014, 1018, 1070, 1074, 1180, 1387,
  1701, 2408, 2506, 3138, 3476, 3581, 3854, 4177, 4198, 4233, 4500, 5279, 5956, 7103, 7152,
  7156, 7281, 7559, 8319, 8742, 8854, 8886;
- по умолчанию проверяется 120 адресов (`IP:порт`), максимум — 4000. Пул формируется расслоённой
  выборкой: каждая пара «подсеть × порт» получает свою долю, поэтому скан не скатывается в одну
  подсеть.

**Как проверяется точка.** Отправляется тот самый профиль шума, который потом пойдёт в работе, и
следом handshake initiation (148 байт). Ответом считается handshake response (92 байта,
проверяются `receiver_index`, MAC1 и тег AEAD) или cookie reply — оба означают «сервер живой и
принимает наш ключ». Молчание и ICMP «порт закрыт» различаются: второе сразу говорит, что порт
закрыт, а не что сеть тормозит. Внутри одной пробы уходит 4 инициации с интервалом 450 мс — первая
датаграмма на мобильной сети теряется регулярно. Параллельно работают 48–64 сокета.

**Профили шума (AmneziaWG).** На каждой из лучших точек проверяется не один вариант, а все: `none`
(чистый WireGuard — на части сетей DPI его не трогает вовсе), `tls-fixed`, `chrome:apteka.ru`,
`quic:` под три SNI из списка российских доменов, `sip`. Сравнивается результат, а не догадка.

`chrome:apteka.ru` — настоящий первый пакет QUIC, с которого Chrome открывает сайт по HTTP/3:
1250 байт, ClientHello с именем apteka.ru, расширениями Chrome и ALPN `h3`, разрезанный на куски
вперемешку с PING и PADDING, как это делает Chrome. Ключи первого пакета QUIC публичны, поэтому
фильтр может его расшифровать — и увидит обычный браузер. Уходит один раз перед каждым
рукопожатием, в том же сеансе радио, поэтому на батарею заметно не влияет. Если рукопожатие
проходит, а данные встали, сервис сначала берёт шум, с которым на этой сети данные уже шли, потом
`chrome:apteka.ru`, потом `tls-fixed`; «без шума» — последним.

**Финал подбора.** Десяток лучших точек поднимается настоящим туннелем, и изнутри по каждой
прогоняются проверки сайтов (см. ниже). Победитель выбирается по числу реально открывшихся сайтов и
только потом по скорости и стабильности; выход за рубежом ставится выше московского (см. раздел 7).
В «Лучших конфигах» остаются три варианта на разных адресах — переключение на запасной занимает одно
нажатие.

На той же сети повторный подбор сначала проверяет прошлую рабочую точку: секунды вместо минут.
Полный скан запускается, только если она перестала работать. Проверочные подъёмы подбора не
запоминаются как «работающая точка».

### 2. Подключение

- **Куда подключается:** к найденной паре `адрес:порт` Cloudflare, по UDP. Промежуточных серверов
  нет: трафик идёт от телефона прямо в ближайший узел Cloudflare.
- **Чем подключается:** собственным `VpnService`. X25519, ChaCha20-Poly1305, BLAKE2s и формат пакетов
  реализованы в проекте (`core/`), поэтому туннель работает без AmneziaVPN и без системного
  WireGuard.
- **Ключи WARP** берутся через те же публичные зеркала, что использует генератор конфигов, и
  кешируются на телефоне; если зеркала недоступны — используется сохранённый аккаунт. Можно вставить
  и свой конфиг. Ключи не покидают устройство.
- **Параметры по умолчанию:** адрес в туннеле `172.16.0.2` (+ IPv6), MTU `1280`, DNS
  `1.1.1.1`/`1.0.0.1`, keepalive 25 с — всё меняется в настройках.
- **Если точка молчит:** при подключении перебирается до шести точек (выбранная → последняя рабочая
  → из подбора → запасные адреса Cloudflare).
- **Перебор можно отменить.** Пока он идёт, главная кнопка называется «Отменить подключение», а ход
  перебора виден строкой над ней. Выключение плиткой в шторке или «Отключить» в уведомлении тоже
  останавливает перебор: следующая точка не стартует, и туннель сам не включится.
- **Рукопожатие по стандарту.** Метка времени в инициации — TAI64N, как в WireGuard: каждая
  следующая строго новее прошлой. WARP её не проверяет, а свой сервер второго выхода проверяет и
  молча отбрасывает инициацию с меткой не новее прежней.

### 3. Удержание туннеля

- **Keepalive** — по настройке (25 с по умолчанию), но с нижней границей: не реже 60 с при активном
  экране и не реже 90 с, когда экран погашен и трафика нет давно. Максимум — 120 с: дольше NAT всё
  равно не помнит соединение. `0` — выключен совсем.
- **Пересогласование сессии (rekey)** — каждые 150 с при живом трафике: протокол жёстко требует
  успеть до 180 с, иначе сервер выбрасывает сессию и снаружи это выглядит как «подключено, но
  Telegram пишет Соединение…». Ответа ждём до 6,6 с: старая сессия в это время действует и везёт
  данные, поэтому пересогласование идёт в фоне и пакеты на нём не стоят. Неудачный rekey повторяется
  через 5 с.
- **Мёртвая сессия.** Если пересогласование дважды не прошло, а сервер за это время не прислал ни
  одного пакета, туннель переподнимается. Если пакеты по нынешней сессии приходят, сеть просто
  медленная: туннель не рвётся, rekey повторяется, пока сессии нет 180 с. Если переподъём не вышел —
  берётся следующая точка из очереди (до шести смен подряд). Если не ответила ни одна, приложение не
  сдаётся и не оставляет мёртвый туннель висеть: новый круг — через растущую паузу (30 с, 1 мин,
  2 мин, дальше раз в 5 минут, всего около 50 минут). Новая сеть или включённый экран запускают
  попытку сразу. Точки, которые просто промолчали, в «мёртвые» записываются, только если в том же
  круге поднялась другая: когда молчат все, дело обычно в сети.
- **Выключил сам — сам и включишь.** Кнопка «Выключить туннель», плитка в шторке и «Отключить» в
  уведомлении — решение человека: после него приложение туннель само не включает — ни
  переподключением, ни фоновым подбором с авто-применением. Переподключается оно, только когда туннель
  упал без вашего участия. Пока сервис ждёт повтора, кнопка и плитка показывают «Выключить» /
  «переподключается» — выключить можно в любой момент.
- **Один сервис — один туннель.** «Отключить» и сразу «Подключить» (так работает перебор точек) не
  порождают второй экземпляр сервиса со своим туннелем на том же ключе. Если система отзывает VPN
  (включили другой VPN), это видно в журнале.
- **Смена сети** (Wi-Fi ↔ мобильные) — переподключение без участия пользователя. UDP-сокет привязан к
  маршруту, и после смены сети его обязательно надо открыть заново, иначе «туннель есть, трафика
  нет». События сети приходят пачкой, поэтому они склеиваются тихим окном 700 мс: переключение
  занимает 1–2 секунды. Смены сети не тратят лимит автоматических переподключений (шесть за
  10 минут): в дороге телефон переходит LTE ↔ H+ ↔ Wi-Fi, и система каждый раз заводит новую сеть.
- **Медленная мобильная связь (H+, H, 3G, EDGE).** Тип связи приложение берёт у системы без
  дополнительных разрешений и пишет в журнал: `сеть туннеля: мобильная 1296 · H+`,
  `мобильная связь: LTE → H+`, `сеть мобильная·H` в строке статистики. На такой связи задержка под
  нагрузкой доходит до секунд, поэтому:
  - рукопожатие ждём до 5,4 с вместо 2,6, проверку «данные идут» — до 8 с вместо 4, проверку связи — до 10 с;
  - замер скорости и проверка медиа Telegram после подъёма не идут: полмегабайта на 0,3–1 Мбит/с заняли
    бы канал как раз тогда, когда приложения переподключаются;
  - остановка данных не записывается шуму и точке: на H/H+ это чаще радио и очередь в соте, чем
    фильтр, а память у мобильной сети общая с LTE;
  - дозор не ходит: его пробы под нагрузкой пометили бы живые точки молчащими.

  Быстрее сама связь от этого не станет: на H — 1–3 Мбит/с, на EDGE — сотни килобит, и это
  ограничение соты, а не туннеля.
- **Память точки по сети.** Приложение запоминает, какой адрес работал на Wi-Fi, а какой — на
  мобильной: адреса Cloudflare не универсальны, и «живой дома» может закрывать порт на LTE. После
  переключения оно начинает с проверенного на такой сети адреса.
- **Готовность сети.** Пока система не признала сеть рабочей (только что включённый Wi-Fi ещё
  раздаёт адрес, портал проверки доступа не пройден), инициации не отправляются впустую: ждём до трёх
  секунд.
- **Провал не досиживают.** Если точка ответила «порт закрыт» или промолчала, переход к следующей
  происходит через доли секунды, а не через 15 секунд ожидания.
- **Дозор.** Пока туннель работает, раз в 12 минут приложение тихо проверяет две точки из очереди
  перебора — ту, на которую перейдёт при обрыве, и ещё одну по кругу: одна-две инициации handshake с
  отдельного сокета мимо туннеля. Текущую сессию это не трогает. Живая точка встаёт в перебор сразу
  за текущей, дважды промолчавшая или ответившая «порт закрыт» уходит в конец. Строка `дозор:` в
  журнале показывает итог каждого обхода. Если промолчали все проверенные точки, дозор пробует ещё и
  текущую с нового сокета: если молчит и она, значит, сеть сейчас не пропускает новые соединения к
  WARP (так ведёт себя DPI), а точки ни при чём — их метки тогда не меняются. То же правило — у
  перебора после обрыва: если туннель в итоге подняла точка, которая в этом же переборе молчала,
  молчала сеть, и порядок перебора остаётся прежним.
- **Честный статус после обновления и перезагрузки.** Обновление приложения и перезагрузка телефона
  закрывают сервис туннеля. Экран это видит сразу и пишет причину. Если туннель перед этим работал и
  его не выключали вручную, он поднимается сам — на последней рабочей конфигурации; так же он ведёт
  себя, когда систему перезапускает сервис или включён «Постоянный VPN» в настройках Android.
- **Проверка точки до переключения.** Выбор из «лучших» сначала проверяется пробой рядом с
  работающим туннелем: если точка молчит, туннель не гаснет, а на экране так и написано — «не
  отвечает, оставил текущую».
- **Без пробуждений вхолостую.** Поток, читающий tun, спит в `poll()` до прихода пакета.
- **Подбор возвращает туннель.** Перед замерами подбор гасит туннель (иначе мерит сам WARP), а по
  окончании поднимает его снова — при любом исходе: нашлась новая точка (тогда на ней), ничего не
  нашлось, подбор отменён или упал (тогда прежнее подключение).
- **«Остановить подбор» останавливает сразу.** Скан, проверки ресурсов и проверка изнутри
  прерываются за секунду-две, недосчитанный результат не сохраняется и не применяется. Подбор
  переживает поворот экрана и возврат в приложение.
- **Долгая тишина.** Если сети нет 45 секунд, туннель снимается, чтобы трафик не уходил в пустоту, —
  но только когда сети действительно нет по системному состоянию. После этого приложение раз в 15
  секунд проверяет, не появилась ли сеть, и поднимает туннель без нажатий.

### 4. Проверка связи и что видно на экране

- **Сайты:** Google (`generate_204`), YouTube, ChatGPT, OpenAI API, Telegram web, Discord, WhatsApp
  web, X, Cloudflare trace — плюс контрольная проверка (`ru.wikipedia.org`), по которой видно, что
  сайт открывается вообще без туннеля.
- **Из-под туннеля:** `cloudflare.com/cdn-cgi/trace` с проверкой `warp=on` (трафик действительно идёт
  через WARP) и `ipinfo.io` — какой адрес и страна видны снаружи. Проверка связи идёт к 1.1.1.1:
  он в туннеле и при неполных маршрутах (DNS идёт через туннель), поэтому выход виден в любом режиме.
- **DNS:** системный резолвер сверяется с двумя независимыми DoH (Cloudflare и Google). Если
  системный отдаёт адреса, которых нет ни в одном из них, — это подмена DNS, и приложение говорит об
  этом прямо, а не «сайт не открывается».
- **Медиа Telegram.** Соединение с сервером Telegram ещё не значит, что грузятся фото и видео:
  фильтры пропускают соединение и режут поток. Поэтому раз в полчаса при включённом экране
  приложение загружает начало официального APK Telegram с telegram.org (до 256 КБ, по IPv4, как ходит
  сам Telegram) и смотрит на скорость и паузы. В журнале — строка `проверка Telegram:` (`медиа ✓`,
  `медиа тормозит`, `медиа рывками`, `медиа встаёт`), на экране — «Telegram: связь есть, медиа
  тормозит». Если сервер загрузки окажется не в сетях Telegram, вывод о медиа не делается.
- **Скорость** — живой поток на самой кнопке раз в секунду. После подъёма (если автоматический замер
  не выключен) — короткий замер через `speed.cloudflare.com`, полмегабайта: заодно видно, что данные
  не встают через пару десятков килобайт («заморозка»); полный, до 10 МБ, — по кнопке.
- **Строка «где мы».** Под кнопкой — вид сети, точка входа, страна выхода WARP и, если второй выход
  поднят, его страна: «мобильная · вход 8.35.211.3:864 · выход RU · второй выход NL». Страна выхода —
  по последней проверке связи; второго выхода нет или он не поднялся — о нём не пишется. Страна
  второго выхода — по серверу Proton («NL-FREE#121»), а у своего сервера — по последней проверке
  второго выхода. В расширенном виде то же — строками «Точка входа / Выход / Второй выход».
  Площадка Cloudflare (`DME`, `HEL`) и что с Telegram — в журнале.

### 5. Второй выход: другая страна для отдельных сайтов

ChatGPT, Claude, Gemini, Grok, Adobe, Canva и другие сервисы не работают с российских адресов, а
выход WARP часто российский. Второй выход пускает их через ваш сервер — остальное идёт через WARP.

1. «Настройки» → «Второй выход»: вставьте клиентский конфиг WireGuard/AmneziaWG или нажмите
   «Выбрать файл .conf».
2. Какие сайты туда идут, подбирается само по отмеченным спискам: «закрытые для российских адресов»
   (Grok, Adobe, Canva, Atlassian и другие), ChatGPT / OpenAI, Claude, Gemini — плюс домены, которые
   вы впишете в поле второго выхода. Поддомены входа (например, `auth.openai.com`) добавляются сами.
   Адреса обновляются раз в сутки.
3. «Сохранить и применить». Кнопка «Обновить адреса и проверить выход» собирает адреса заново и
   проверяет, из какой страны выходит запрос.

Если сервер недоступен, его адреса возвращаются в WARP: сайт работает, регион другой, туннель не
рвётся — об этом строка в журнале. Ограничения: сайты на общих CDN-адресах могут уйти не через тот
выход; для Outline/Shadowsocks второй выход не подходит — им нужен TCP-стек.

**Proton VPN Free.** «Как подключить Proton» показывает, что нажать на сайте Proton (Downloads →
WireGuard configuration → Free server configs → Create → Download), и открывает сайт. Сайт Proton в
России заблокирован — открывайте его при включённом WarpScout или на компьютере. Скачанный файл
выбирается кнопкой «Выбрать файл .conf» — конфиг встаёт в поле, второй выход включается; разрешений
приложению это не добавляет. Для такого конфига приложение само перебирает бесплатные серверы Proton
и меняет сервер, если он перестал отвечать. При стране «Любая» сначала пробуются ближние страны —
Нидерланды, Польша, Румыния, Швейцария, Норвегия, — и только потом сервер из самого конфига и дальние
(Канада, США, Япония, Сингапур, Мексика). Выбранная вручную страна идёт первой.

### 6. Разделение трафика

- **По приложениям:** всё через туннель, только выбранные, всё кроме выбранных. Выбор — на вкладке
  «Туннелирование» и в шторке упрощённого вида.
- **Выход по приложениям** (Android 10+, когда включён второй выход) — кнопка в строке приложения:
  - **«Само»** — второй выход только для сайтов из его списков;
  - **«WARP»** — всегда через WARP, даже к сайтам второго выхода. Так Telegram остаётся на выходе
    WARP, где у него грузятся медиа, а второй выход продолжает работать для остальных; вопрос
    «переключить Telegram?» для него не приходит;
  - **«Второй выход»** — приложение целиком через свой сервер (Aurora Store, Grok, Claude).

  Выбрали выход — приложение само идёт через туннель (отмечается в «только выбранные», убирается из
  исключений). Чьё соединение, сервис спрашивает у Android (`getConnectionOwnerUid`) один раз на
  соединение и только когда ответ что-то меняет; DNS идёт как обычно. Если второй выход не поднялся,
  такие приложения идут через WARP — об этом строка в журнале.
- **По сайтам:** весь трафик, встроенные наборы, списки allow-domains или свои сайты и CIDR. Списки
  скачиваются из источника и разворачиваются в маршруты. Маршруты всегда текущие: с какой бы точки ни
  поднимался туннель — из топа, из очереди, после обновления или перезагрузки, — они берутся из
  «Туннелирования», а не из конфига, сохранённого при подборе. Собирать отдельно не нужно:
  «Сохранить и применить» само скачивает недостающие списки и собирает то, что не собрано или
  собрано под другие отметки. Кнопка «Обновить списки» — чтобы освежить уже собранное: скачивает
  списки заново и пересобирает адреса (сайты переезжают на новые адреса), а туннель не трогает —
  новые адреса поднимутся со следующим подключением, сразу — по «Сохранить и применить».
- **Известные приложения — целиком.** Telegram, Instagram, Facebook, WhatsApp, YouTube, X, Discord,
  ChatGPT, Claude, Gemini, Grok, Aurora Store ходят в свои сети, и в режимах «сайты из списков» и «мои
  сайты» эти сети добавляются к маршрутам — отмеченное приложение идёт через туннель целиком.
  Приложения, чьих сетей WarpScout не знает, при неполных маршрутах идут только к выбранным сайтам —
  об этом предупреждает строка приложения и сводка «Сейчас через туннель».
- **Браузер — только к нужным сайтам** (переключатель в «Туннелировании», включён). Android сначала
  решает по приложению, а адреса у туннеля общие для всех выбранных приложений. Поэтому, если среди
  выбранных есть браузер, маршруты — не «весь трафик», а сайты второго выхода, «Мои сайты» и
  отмеченные списки плюс сети выбранных приложений: из браузера через туннель идут только эти сайты
  (и сайты тех же сервисов: youtube.com, instagram.com), остальное — напрямую. Браузер узнаётся по
  тому, что открывает любую ссылку https. Галочки списков и «Мои сайты» в этом режиме режим сайтов
  не переключают: это и есть сайты браузера.
- **YouTube при неполных маршрутах.** Видео идёт с серверов googlevideo.com, их адреса выдаются под
  каждое видео, и заранее в список их не внести. Если YouTube в туннеле (отмечен его список, выбрано
  приложение или он есть в своих сайтах), к маршрутам сами добавляются сети Google, откуда идёт видео.
- **GitHub при неполных маршрутах.** Сети GitHub всегда в маршрутах туннеля: через них идут
  обновления WarpScout и списки сайтов, а напрямую GitHub у операторов бывает недоступен.
- **Gemini — вместе с приложением Google.** Gemini на Android — оболочка: запросы к Google, и проверку
  страны тоже, делает приложение Google. Поэтому в режиме «только выбранные» оно идёт через туннель
  вместе с отмеченным Gemini (подпись «с ним пойдёт приложение Google»). Если Gemini всё равно пишет
  «Эта страна не поддерживается», он помнит прежний ответ: остановите приложение Google («Настройки →
  Приложения → Google → Остановить») и очистите данные Gemini.
- **Grok — через второй выход.** xAI сам отказывает российским адресам, поэтому grok.com и x.ai идут
  во второй выход вместе со списком «закрытые для российских адресов», а приложение Grok
  (`ai.x.grok`) — среди известных.
- **Приложений нет в российском Google Play** («Недоступно в вашей стране» у Claude, Grok и других).
  Play показывает каталог страны аккаунта (платёжного профиля), а не страны IP-адреса, поэтому
  туннель тут не поможет. Такие приложения можно поставить через Aurora Store — открытый клиент
  Google Play: при анонимном входе аккаунт берётся с сервера Aurora, каталог у него не российский, а
  файлы те же, с серверов Google и с подписью разработчика. Поставили — отметьте приложение в
  «Туннелировании».

### 7. Выход WARP через Москву

WARP выходит в интернет через площадку Cloudflare, которую выбирает маршрут оператора: `HEL` —
Хельсинки, `DME` — Москва. Через московскую площадку трафик попадает под российские фильтры: так
замедляют медиа Telegram («соединение быстрое, а фото и видео грузятся рывками»). Разные подсети
Cloudflare приходят на разные площадки, поэтому:

- **Подбор узнаёт площадку каждой точки** — запросом `id.server` к 1.1.1.1 внутри той же пробы
  данных — и ставит выход за рубежом выше московского (в баллах, в тройке каждой сети и в переборе
  при обрыве). Если на сети за рубежом не выходит ни одна точка, так и пишется в журнал.
- **Поиск выхода за рубежом** (переключатель в «Автоматике»): если проверка связи показала выход в
  России, приложение ищет точку с выходом за рубежом — только на зарядке с погашенным экраном
  (5 минут), не чаще раза в сутки на сеть. Туннель гаснет на минуту-две и возвращается сам, а
  включённый экран прерывает поиск сразу.
- **Telegram — через второй выход только по вашему ответу** (переключатель «Telegram: предлагать
  второй выход» в «Автоматике»). Telegram идёт через WARP, даже если выход в Москве: режут там не
  всегда, а второй выход бывает медленнее. Если проверка медиа через Москву показала «тормозит», та
  же загрузка идёт через второй выход, и если он заметно быстрее, приходит уведомление с цифрами:
  «Через Москву: 300 Кбит/с, медленно. Через второй выход (Нидерланды): 4,1 Мбит/с. Переключить
  Telegram?» — кнопки «Переключить» и «Оставить». Ответ действует сутки для этой сети; без ответа
  приложение не спрашивает снова три часа. После «Переключить» приложение меряет оба пути и, если
  второй выход стал медленнее Москвы, само возвращает Telegram через WARP. Если уведомления
  выключены, тот же вопрос задаёт окно на открытом экране. Переключение — на лету, без
  переподключения; живые соединения Telegram не рвутся. Нужен настроенный второй выход.
- **Эксперимент: выход для приложений — сам** (переключатель в «Автоматике», по умолчанию выключен).
  Для приложений с выходом «Само» — YouTube, Instagram, Facebook, WhatsApp, X, Discord, ChatGPT,
  Claude, TikTok — туннель раз в 30 минут при включённом экране (и не на медленной связи) открывает
  их сайт через WARP и через второй выход (до 100 КБ каждый раз) и ведёт приложение туда, где сервис
  работает: открывается только через второй выход — приложение целиком идёт через него; открывается
  обоими путями — через WARP, а через второй выход — только если через WARP вдвое медленнее; когда
  WARP догоняет, приложение возвращается. Чьё соединение, сервис узнаёт так же, как для выхода по
  приложениям; переезжают только новые соединения по IPv4, идущие не рвутся (после возврата они ещё
  10 минут идут прежним путём). Замер идёт своим соединением, закреплённым за выходом: направлять его
  по адресу нельзя — тем же адресом в эти секунды пользуется само приложение. Telegram — как раньше,
  своей проверкой медиа. Итог замера — под переключателем и в журнале («автовыбор выхода: …»).
  Менять точку под открытое приложение не получится: какое приложение открыто, Android говорит только
  с доступом к истории использования (его нет с 1.10.32), а смена точки рвёт соединения всех
  приложений. Вместо этого при включённом переключателе в отчёте подбора появляется раздел
  «Приложения по точкам»: как каждый сервис из «Что проверять» открылся через каждую из трёх
  проверенных изнутри точек (нужна «При подборе проверять через туннель трёх лучших точек»), с
  пометкой «≈ одинаково», если разница меньше разброса одного запроса (четверть секунды или половина
  лучшего времени), и строкой про второй выход из последнего замера автовыбора.

## Что и как часто

| Что происходит | Как часто | Зачем |
|---|---|---|
| keepalive | 25 с (по настройке), не чаще 60 с при живом экране, не чаще 90 с в тишине с погашенным экраном, максимум 120 с | держать NAT-таблицу и сессию живыми |
| пересогласование сессии (rekey) | каждые 150 с при трафике; повтор через 5 с | протокол требует успеть до 180 с |
| попытка handshake | 4 инициации с интервалом 450 мс | первая датаграмма на мобильной сети теряется |
| проверка «а жива ли сессия» | на каждом отправленном пакете, без таймеров | заметить мёртвую сессию за секунды, а не за минуты |
| проверка связи (и выход WARP) | после подъёма, при открытии экрана и когда пакеты уходят без ответа | «подключено» = «данные ходят» |
| строка статистики в журнале | раз в 5 минут (в глубоком сне реже — тогда пишется настоящая длина интервала) | видно, что именно расходует батарею |
| проверка медиа Telegram | при проверке связи, если экран включён: не чаще раза в 30 минут или при смене площадки, до 256 КБ; если через Москву тормозит — ещё раз через второй выход (а после «Переключить» — оба пути), до 512 КБ | увидеть «связь есть, медиа тормозит» и понять, поможет ли второй выход |
| поиск выхода за рубежом | выход в России, зарядка, экран погашен 5 минут — не чаще раза в сутки на сеть | уйти с московской площадки без нажатий |
| замер скорости | после подъёма — короткий (полмегабайта), если не выключен; полный (до 10 МБ) — по кнопке; в финале подбора — четверть мегабайта на точку | заметить «заморозку», показать скорость, выбрать из равных точек более быструю |
| адреса второго выхода | раз в сутки и по кнопке | сайты меняют адреса |
| проверки сайтов | при подборе и по кнопке «Проверить» | «открывается» вместо «наверное, работает» |
| фоновый подбор | выключен по умолчанию; 6–12 часов, если включить | обновить точку, когда сеть изменилась |
| смена точки входа | при обрыве: сразу следующая из очереди, до 6 подряд; не ответила ни одна — новый круг через 30 с, 1, 2, затем 5 мин | подняться без ручного нажатия |
| попытка при включении экрана | только когда туннель лежит и ждёт повтора; не чаще раза в 30 с | не ждать паузы, когда человек смотрит на телефон |
| дозор очереди перебора | раз в 12 минут при поднятом туннеле (первый — через 3 минуты): 2 точки, 1–2 инициации на каждую | при обрыве сразу перейти на живую точку |
| проверка обновлений | только по кнопке | без фоновых запросов |

## Куда обращается приложение

| Адрес | Что это | Когда используется |
|---|---|---|
| `162.159.192.*`, `162.159.195.*`, `188.114.96–99.*`, `8.*.*.*` Cloudflare | точки входа WARP, UDP | подбор, подключение и дозор очереди перебора |
| `engage.cloudflareclient.com:2408` | тот же WARP, по имени | как обычная точка |
| зеркала `warp-api.cfd` | выдача ключей WARP | первый запуск и обновление аккаунта |
| `cloudflare-dns.com/dns-query`, `dns.google/resolve` | DoH | сборка адресов для второго выхода, сверка DNS |
| проверяемые сайты (см. раздел 4) | HTTP(S)-запросы | проверки при подборе и по кнопке |
| `1.1.1.1/cdn-cgi/trace`, `cloudflare.com/cdn-cgi/trace` | выход и признак `warp=on` | проверка связи |
| `1.1.1.1` (запрос `id.server` внутри пробы WARP) | площадка выхода точки | подбор |
| `speed.cloudflare.com` | замер скорости | после подъёма (короткий), по кнопке и в финале подбора |
| `telegram.org` (начало `/dl/android/apk`, до 256 КБ) | проверка медиа Telegram | проверка связи, не чаще раза в 30 минут |
| `chatgpt.com/cdn-cgi/trace` через второй выход | из какой страны выходит второй выход | после «Сохранить и применить» и по кнопке |
| `api.github.com`, `github.com`, `release-assets.githubusercontent.com` | последний релиз и его APK | по кнопке «Проверить обновления»; при неполных маршрутах — через туннель |
| `raw.githubusercontent.com` | списки сайтов (allow-domains) и серверов Proton Free (gluetun) | сборка адресов второго выхода и списков |

Приложение не создаёт аккаунтов, не собирает телеметрию, не показывает рекламу и не отправляет
никуда ничего, кроме перечисленных запросов. Ключи, конфиги и журналы лежат в приватном каталоге
приложения; приватный ключ дополнительно шифруется ключом из Android Keystore.

## Батарея

| Состояние | Расход |
|---|---|
| приложение закрыто, туннель выключен | практически ноль: нет wakelock, нет будильников, фоновый подбор выключен |
| туннель поднят, экран погашен, Wi-Fi | около 1 % в час (измерено: 4 % за 94 минуты при 48–150 мА, модем 0 Б) |
| туннель поднят, экран погашен, мобильная сеть | 1–3 % в час: пробуждение радиомодуля дороже самого пакета |
| туннель поднят, телефон в работе | меньше, чем расходует сам экран |
| подбор конфигурации | обычный скан — единицы процентов; полный перебор — десятки: минуты непрерывной работы радио |

Проверить это можно по журналу: строка `статистика:` раз в 5 минут показывает keepalive,
рукопожатия, байты вверх/вниз, секунды без трафика, процессорное время по потокам,
переподключения, смены сети, заряд, ток, израсходованные мА·ч и трафик модема. По ней видно, что
именно ело батарею — процессор при малом трафике, частые переподключения или сам модем.

## Сборка из исходников

```bash
git clone https://github.com/kos19191/warp-scout-src
cd warp-scout-src

./gradlew :app:assembleTunnelDebug      # открывается упрощённым экраном
./gradlew :app:assembleScoutDebug       # то же, открывается расширенным экраном
./gradlew :core:check                   # самопроверка протокольного слоя
```

Нужны JDK 17 и Android SDK (compileSdk 35). Для релизной подписи — `app/release.keystore` и
переменные `WARPSCOUT_STOREPASS`, `WARPSCOUT_KEYALIAS`, `WARPSCOUT_KEYPASS`; без них используется
debug-ключ.

```
core/   протокольный слой: WireGuard/AmneziaWG, криптография, подбор, маршруты, списки
app/    Android-приложение: экраны, VpnService, настройки, обновления, экспорт
cli/    консольный вариант подбора (без Android)
tools/  оффлайн-проверки для CI
```

```bash
./gradlew :cli:installDist
./build/install/cli/bin/cli tune --profiles 4 --count 200
```

**Проверки в CI:** `tools/android_stub_check.py` (ресурсы и разметка без SDK), самопроверка
протокольного слоя (`SelfCheck`: криптография, handshake, разбор конфигов, маршрутизация),
векторы фейкового WARP-сервера на независимой реализации на Python, интеграционный прогон «наш
клиент против Python-сервера», сборка обеих APK. Релиз собирается по тегу `v*`; на странице релизов
остаются пять последних версий.
