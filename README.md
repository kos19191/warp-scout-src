# WarpScout

Android-приложение для работы через Cloudflare WARP. Оно само находит в вашей сети адрес
Cloudflare, который пропускает трафик, поднимает на нём туннель и держит его — без ручного
перебора адресов, без сторонних VPN-библиотек и без сервера-посредника.

Проект не аффилирован с Cloudflare. Это клиент, который реализует протокол сам: обмен ключами,
handshake, сессии, пересогласование, разбор пакетов, маршрутизацию. Всё, с чем приложение
разговаривает, — это адреса Cloudflare и ваш телефон.

---

## Что делает приложение

- **Подбирает рабочую точку входа.** Перебирает адреса и порты Cloudflare WARP, проверяет их
  настоящим handshake, а не пингом, и оставляет те, что ответили именно вашему ключу.
- **Поднимает туннель само.** Свой `VpnService`: WireGuard/AmneziaWG внутри приложения,
  без внешних библиотек. Подключение — одно нажатие, при обрыве поднимается заново без вас.
- **Меняет точку, когда прежняя умерла.** Держит очередь проверенных адресов и переходит на
  следующий сам — в том числе ночью, когда никто не нажимает кнопок.
- **Показывает, что реально открывается.** Прогоняет список сайтов из-под туннеля и говорит
  «открылось / не открылось», а не «подключено, наверное, работает».
- **Умеет отправить часть трафика в свою страну.** WARP — anycast, страну выхода выбрать нельзя;
  для отдельных сайтов можно добавить свой WireGuard/AmneziaWG-сервер.
- **Разделяет трафик.** По приложениям и по адресам: всё в туннель, только выбранные, всё кроме
  выбранных.
- **Объясняет отказы по-русски.** В журнале видно каждый шаг с временем и длительностью, и что
  делать, если не поднялось.
- **Показывает, сколько туннель уже работает.** Время считается от подъёма сессии, а не от
  открытия экрана, — часы работы видно и после перезапуска приложения. Журнал открывается на самых
  свежих строках и листается, разделы переключаются кнопками снизу или смахиванием влево-вправо.

## Как это работает

### 1. Подбор точки входа

Cloudflare WARP отвечает на любой из своих anycast-адресов, но в каждой сети часть адресов и
портов закрыта. Приложение перебирает их и проверяет по-настоящему.

**Что перебирается:**

- подсети Cloudflare WARP: `162.159.192.*`, `162.159.195.*`, `8.6.112.*`, `8.34.70.*`,
  `8.34.146.*`, `8.35.211.*`, `8.39.125.*`, `8.39.204.*`, `8.39.214.*`, `8.47.69.*`,
  `188.114.96.*`…`188.114.99.*`, плюс имя `engage.cloudflareclient.com`;
- октеты `1…10` внутри подсети (не весь /24: разницы в поведении нет, а скан в 25 раз короче);
- порты из документации WARP: 500, 854, 859, 864, 878, 880, 890, 891, 894, 903, 908, 928, 934,
  939, 942, 943, 945, 946, 955, 968, 987, 988, 1002, 1010, 1014, 1018, 1070, 1074, 1180, 1387,
  1701, 2408, 2506, 3138, 3476, 3581, 3854, 4177, 4198, 4233, 4500, 5279, 5956, 7103, 7152,
  7156, 7281, 7559, 8319, 8742, 8854, 8886;
- по умолчанию проверяется 120 адресов (`IP:порт`), максимум — 4000. Пул формируется
  расслоённой выборкой: каждая пара «подсеть × порт» получает свою долю, поэтому скан не
  скатывается в одну подсеть.

**Как проверяется точка.** Отправляется тот самый профиль мусора, который потом пойдёт в
работе, и следом handshake initiation (148 байт). Считается ответом handshake response (92 байта,
проверяются `receiver_index`, MAC1 и тег AEAD) или cookie reply — оба означают «сервер живой и
принимает наш ключ». Молчание и ICMP «порт закрыт» различаются: второе сразу говорит, что порт
закрыт, а не что сеть тормозит. Внутри одной пробы уходит 4 инициации с интервалом 450 мс —
первая датаграмма на мобильной сети теряется регулярно. Параллельно работают 48–64 сокета.

**Профили шума (AmneziaWG).** На каждой из лучших точек проверяется не один вариант, а все:
`none` (чистый WireGuard — на части сетей DPI его не трогает вовсе), `tls-fixed`, `quic:` под три
SNI из списка российских доменов, `sip`. Сравнивается результат, а не догадка.

**Финал подбора.** Десяток лучших точек поднимается настоящим туннелем, и изнутри по каждой
прогоняются проверки сайтов (см. ниже). Победитель выбирается по числу реально открывшихся
сайтов, и только потом по скорости и стабильности. В «Лучших конфигах» остаются три варианта на
разных адресах — переключение на запасной занимает одно нажатие.

На той же сети повторный подбор сначала проверяет прошлую рабочую точку: секунды вместо минут.
Полный скан запускается, только если она перестала работать.

### 2. Подключение

- **Куда подключается:** к найденной паре `адрес:порт` Cloudflare, по UDP. Никаких промежуточных
  серверов: трафик идёт от телефона прямо в ближайший узел Cloudflare.
- **Чем подключается:** собственным `VpnService`. X25519, ChaCha20-Poly1305, BLAKE2s и формат
  пакетов реализованы в проекте (`core/`), поэтому туннель работает без AmneziaVPN и без
  системного WireGuard.
- **Ключи WARP:** берутся через те же публичные зеркала, что использует генератор конфигов, и
  кешируются на телефоне; если зеркала недоступны — используется сохранённый аккаунт. Можно
  вставить и свой конфиг. Ключи не покидают устройство.
- **Параметры по умолчанию:** адрес в туннеле `172.16.0.2` (+ IPv6), MTU `1280`, DNS
  `1.1.1.1`/`1.0.0.1`, keepalive 25 с — всё меняется в настройках.
- **Если точка молчит:** при подключении перебирается до шести точек (выбранная → последняя
  рабочая → из подбора → запасные адреса Cloudflare).

### 3. Удержание туннеля

- **Keepalive** — по настройке (25 с по умолчанию), но с нижней границей: не реже 60 с при
  активном экране и не реже 90 с, когда экран погашен и трафика нет давно. Максимум — 120 с:
  дольше NAT всё равно не помнит соединение. `0` — выключен совсем.
- **Пересогласование сессии (rekey)** — каждые 150 с при живом трафике: протокол жёстко требует
  успеть до 180 с, иначе сервер выбрасывает сессию и снаружи это выглядит как «подключено, но
  Telegram пишет Соединение…». Неудачный rekey повторяется через 5 с.
- **Мёртвая сессия.** Если пересогласование не прошло, туннель переподнимается; если и это не
  вышло — берётся следующая точка из очереди (до шести смен подряд). Бесконечного цикла нет:
  после этого — одна попытка раз в 5 минут в течение часа.
- **Смена сети** (Wi-Fi ↔ мобильные) — переподключение без участия пользователя. UDP-сокет
  привязан к маршруту, и после смены сети его обязательно надо открыть заново, иначе «туннель
  есть, трафика нет». События сети приходят пачкой, поэтому они склеиваются тихим окном 700 мс:
  переключение занимает 1–2 секунды, а не 5–8.
- **Память точки по сети.** Приложение запоминает, какой адрес работал на Wi-Fi, а какой — на
  мобильной: адреса Cloudflare не универсальны, и «живой дома» может закрывать порт на LTE.
  Поэтому после переключения оно сразу начинает с проверенного на такой сети адреса, а не с
  адреса из другой сети.
- **Готовность сети.** Пока система не признала сеть рабочей (только что включённый Wi-Fi ещё
  раздаёт адрес, портал проверки доступа не пройден), инициации не отправляются впустую: ждём до
  трёх секунд. Это и быстрее, и меньше расхода модема.
- **Провал не досиживают.** Если точка ответила «порт закрыт» или промолчала, переход к
  следующей происходит через доли секунды, а не через 15 секунд ожидания.
- **Долгая тишина.** Если сети нет 45 секунд, туннель снимается, чтобы трафик не уходил в
  пустоту, — но только когда сети действительно нет: проверка идёт по системному состоянию, а не
  по внутреннему флагу. И сразу после снятия приложение само проверяет раз в 15 секунд, не
  появилась ли сеть, — поднимает туннель без нажатий.

### 4. Что проверяется после подъёма

- **Сайты:** Google (`generate_204`), YouTube, ChatGPT, OpenAI API, Telegram web, Discord,
  WhatsApp web, X, Cloudflare trace — плюс контрольная проверка (`ru.wikipedia.org`), по которой
  видно, что сайт открывается вообще без туннеля.
- **Из-под туннеля:** `cloudflare.com/cdn-cgi/trace` с проверкой `warp=on` (значит, трафик
  действительно идёт через WARP) и `ipinfo.io` — какой адрес и страна видны снаружи.
- **DNS:** системный резолвер сверяется с двумя независимыми DoH (Cloudflare и Google). Если
  системный отдаёт адреса, которых нет ни в одном из них, — это подмена DNS, и приложение
  говорит об этом прямо, а не «сайт не открывается».
- **Регион выхода** через WARP определяется один раз после подъёма по `cdn-cgi/trace`
  (например, `HEL · RU`), чтобы было видно, куда именно ведёт текущий туннель.
- **Скорость** замеряется через `speed.cloudflare.com`, если запустить замер из отчёта.

### 5. Второй выход: своя страна для отдельных сайтов

WARP — anycast: узел выбирает Cloudflare по вашей сети, страну выбрать нельзя. Если нужен
конкретный регион для конкретных сайтов, нужен свой сервер.

1. Поднимите WireGuard или AmneziaWG на любом VPS в нужной стране.
2. **Настройки → Второй выход (регион)**: вставьте клиентский конфиг, перечислите домены.
3. **«Собрать IP из доменов»** — домены развернутся в адреса через DoH (`/32` и `/128`).
4. **«Сохранить и применить»**.

Пакеты на эти адреса пойдут через ваш сервер, всё остальное — через WARP. Если сервер недоступен,
его подсети возвращаются в WARP: сайт работает, регион другой, туннель не рвётся. Ограничения:
сайты на общих CDN-адресах могут уйти не через тот выход; для Outline/Shadowsocks второй выход не
подходит — им нужен TCP-стек.

### 6. Разделение трафика

- **По приложениям:** всё через туннель, только выбранные, всё кроме выбранных.
- **По адресам:** весь трафик, встроенные наборы, списки allow-domains или свои CIDR.
  Списки скачиваются из источника, разворачиваются в маршруты и используются в `AllowedIPs`.

## Что и как часто

| Что происходит | Как часто | Зачем |
|---|---|---|
| keepalive | 25 с (по настройке), не чаще 60 с при живом экране, не чаще 90 с в тишине с погашенным экраном, максимум 120 с | держать NAT-таблицу и сессию живыми |
| пересогласование сессии (rekey) | каждые 150 с при трафике; повтор через 5 с | протокол требует успеть до 180 с |
| попытка handshake | 4 инициации с интервалом 450 мс | первая датаграмма на мобильной сети теряется |
| проверка «а жива ли сессия» | на каждом отправленном пакете, без таймеров | заметить мёртвую сессию за секунды, а не за минуты |
| строка статистики в журнале | раз в 5 минут (в глубоком сне реже — тогда пишется настоящая длина интервала) | видно, что именно расходует батарею |
| определение региона выхода | один раз после подъёма | показать, куда ведёт туннель |
| проверки сайтов | при подборе и по кнопке «Проверить» | «открывается» вместо «наверное, работает» |
| фоновый подбор | выключен по умолчанию; 6–12 часов, если включить | обновить точку, когда сеть изменилась |
| смена точки входа | при обрыве: сразу следующая из очереди, до 6 подряд | подняться без ручного нажатия |

## Куда обращается приложение

| Адрес | Что это | Когда используется |
|---|---|---|
| `162.159.192.*`, `162.159.195.*`, `188.114.96–99.*`, `8.*.*.*` Cloudflare | точки входа WARP, UDP | подбор и подключение |
| `engage.cloudflareclient.com:2408` | тот же WARP, по имени | как обычная точка |
| зеркала `warp-api.cfd` | выдача ключей WARP | первый запуск и обновление аккаунта |
| `cloudflare-dns.com/dns-query`, `dns.google/resolve` | DoH | сборка адресов для второго выхода, сверка DNS |
| проверяемые сайты (см. список выше) | HTTP(S)-запросы | проверки при подборе и по кнопке |
| `cloudflare.com/cdn-cgi/trace` | регион и признак `warp=on` | после подъёма туннеля |
| `speed.cloudflare.com` | замер скорости | по кнопке в отчёте |

Приложение не создаёт аккаунтов, не собирает телеметрию, не показывает рекламу и не отправляет
никуда ничего, кроме перечисленных запросов. Ключи, конфиги и журналы лежат в приватном каталоге
приложения; приватный ключ дополнительно шифруется ключом из Android Keystore.

## Батарея

| Состояние | Расход |
|---|---|
| приложение закрыто, туннель выключен | практически ноль: нет wakelock, нет будильников, фоновый подбор выключен |
| туннель поднят, экран погашен, Wi-Fi | около 1 % в час (измерено: 4 % за 94 минуты при 48–150 мА, модем 0 Б) |
| туннель поднят, экран погашен, мобильная сеть | 1–3 % в час: пробуждение радиомодуля дороже самого пакета |
| туннель поднят, телефон в работе | меньше, чем расходует сам экран |
| подбор конфигурации | обычный скан — единицы процентов; полный перебор — десятки: минуты непрерывной работы радио |

Проверить это можно по журналу: строка `статистика:` раз в 5 минут показывает keepalive,
рукопожатия, байты вверх/вниз, секунды без трафика, процессорное время по потокам,
переподключения, смены сети, заряд, ток, израсходованные мА·ч и трафик модема. По ней видно, что
именно ело батарею — процессор при малом трафике, частые переподключения или сам модем.

## Требования и установка

- Android 8.0 и новее.
- При первом подключении система спросит разрешение на VPN — без него туннель не поднимется.
- Для «только выбранные / всё кроме выбранных» нужен доступ к списку приложений; для расхода по
  приложениям — доступ к статистике использования. Приложение объясняет, зачем это.

Установка APK из файла: разрешите «Установка неизвестных приложений» для файлового менеджера или
браузера, которым открываете файл. Обновление ставится поверх предыдущей версии: настройки, ключи
и подобранный конфиг сохраняются.

## Релизы

Готовые APK — в разделе [Releases](../../releases). В каждом релизе два файла:

| Сборка | Что внутри | Application ID |
|---|---|---|
| `WarpScout-<версия>-tunnel.apk` | полная: подбор, собственный туннель, проверки из-под него | `dev.warpscout.app.tunnel` |
| `WarpScout-<версия>-scout.apk` | только подбор, генерация и экспорт конфигов для AmneziaVPN | `dev.warpscout.app` |

- Обе сборки можно держать на телефоне одновременно: идентификаторы различаются.
- Сборки **debug-подписанные**: годятся для сайдлоада и тестов, не для магазина приложений.
- Контрольные суммы SHA-256 лежат в том же релизе (`SHA256SUMS.txt`).
- На странице релизов хранятся три последние версии: при выпуске новой самая старая удаляется
  вместе с тегом, поэтому откатиться на одну-две версии назад можно всегда.

## Сборка из исходников

```bash
git clone https://github.com/kos19191/warp-scout-src
cd warp-scout-src

./gradlew :app:assembleTunnelDebug      # полная сборка
./gradlew :app:assembleScoutDebug       # только подбор
./gradlew :core:check                   # самопроверка протокольного слоя
```

Нужны JDK 17 и Android SDK (compileSdk 35). Для релизной подписи — `app/release.keystore` и
переменные `WARPSCOUT_STOREPASS`, `WARPSCOUT_KEYALIAS`, `WARPSCOUT_KEYPASS`; без них используется
debug-ключ.

```
core/   протокольный слой: WireGuard/AmneziaWG, криптография, подбор, маршруты, списки
app/    Android-приложение: экраны, VpnService, настройки, экспорт
cli/    консольный вариант подбора (без Android)
tools/  оффлайн-проверки для CI
```

```bash
./gradlew :cli:installDist
./build/install/cli/bin/cli tune --profiles 4 --count 200
```

**Проверки в CI:** `tools/android_stub_check.py` (ресурсы и разметка без SDK), самопроверка
протокольного слоя (`SelfCheck`: криптография, handshake, разбор конфигов, маршрутизация),
векторы фейкового WARP-сервера на независимой реализации на Python, интеграционный прогон
«наш клиент против Python-сервера», сборка обеих APK.
