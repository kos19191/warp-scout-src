# WarpScout

Android-приложение, которое **само подбирает рабочую WARP/AWG-конфигурацию** и отдаёт её вам в
AmneziaVPN — или поднимает туннель само.

Сделано под конкретную боль: конфигурации Cloudflare WARP в amneziaVPN живут недолго — оператор
режет порты, endpoint'ы перестают отвечать, шумовые параметры (`I1/I2/Jc/Jmin/Jmax`) suddenly
блокируются, и приходится вручную перебирать IP и порты. WarpScout делает этот перебор сам,
меряет результат не «пингом», а доступностью реальных сервисов, и перегенерирует конфиг, когда
прежний перестал работать.

---

## Что он делает

```
ключи из публичного генератора  →  пул endpoint'ов  →  скан  →  скоринг  →  отчёт + .conf  →  Amnezia / туннель
        (приватный ключ никуда   (подсети × порты,    AWG       лучший     json/csv/md/html   импорт в 1 тап
         не вводится)             + ваши строки)      handshake вердикт    + проверки ресурсов
```

1. **Ключи.** Приватный ключ генерируется на стороне публичного генератора WARP
   (`https://warp-workers.warp-api.cfd` и четыре зеркала: `warp-sub`,
   `warp-vercel-chi`, `warp-vercel-murex`, `warp-netlify`; запрос с заголовком `X-Client: WARP`,
   ответ — `{privKey, peer_pub, client_ipv4, client_ipv6}`; для MASQUE есть `masque-workers`
   и `masque-vercel`).
   Ничего вводить не нужно. Ответ кэшируется в AndroidKeyStore (AES/GCM), поэтому при недоступных
   зеркалах конфиг собирается из кэша. Ручной импорт `.conf` — запасной путь: «Поделиться →
   WarpScout» или `warp-scout://`.
2. **Пул endpoint'ов.** По умолчанию — подсети Cloudflare (`162.159.192.*`, `188.114.96-99.*`,
   `8.6.112.*`, `8.34.*`, …) × 52 порта AWG (500, 854, 859, … 8886), плюс `engage.cloudflareclient.com`.
   Можно вписать свой список: `8.6.112.*:943`, `188.114.96.1-10:443`, `host.example:2408`.
3. **Скан.** Для каждой точки отправляется настоящий WireGuard/AWG initiation-пакет (148 байт,
   X25519 + BLAKE2s, собственная реализация протокола — см. `core/.../wg/Wg.kt`) и смотрим ответ:
   handshake response / cookie reply / тишина / ICMP unreachable. Для MASQUE-портов (443, 8443, …)
   вместо этого проверяется TLS. Всё это — **до** туннеля, как его проверяет и человек руками.
4. **Обфускация.** Каждый endpoint прогоняется через профили шума: `none`, `tls-fixed`
   (1250-байтовый псевдо-TLS Handshake), `quic:<sni>` (QUIC Initial с обрезанным ClientHello под SNI
   из белого списка: `ivi.ru`, `akbars.ru`, `deepseek.com`, …), `sip-invite` (348/490 байт). Плюс
   параметры AWG (`Jc`, `Jmin`, `Jmax`, `Idle`, `Death`, `Handshake*`). Профиль, который DPI
   пропускает, побеждает профиль, который режет.
5. **Проверка ресурсов.** Не «порт открыт», а «работает ли»: ChatGPT, Google, YouTube, Discord,
   Telegram, WhatsApp, Instagram, `speed.cloudflare.com` — и отдельно измеряется базовая доступность
   **без** туннеля, чтобы не засчитать приложению успех там, где и так всё работает.
   В режиме встроенного туннеля (`tunnel`) тот же набор проверяется ещё раз **из-под туннеля** —
   это единственный честный способ отличить «эндпоинт отвечает» от «трафик идёт».
6. **Отчёт.** Каждый кандидат с разбором балла (почему 860, а не 40), тайминги, число повторов,
   живость ресурсов. Форматы: `json`, `csv`, `md`, `html`.
7. **Конфиг.** Готовый `*.conf` (WireGuard/AWG-формат с AWG-ключами и мусором), `Address`, `DNS`,
   `MTU`, `PersistentKeepalive`, split-tunnel по белому списку (56 префиксов: Яндекс, VK, Ozon,
   госуслуги, `.ru`-CDN и т. п., чтобы не гонить лишнее через туннель). Плюс Clash-YAML.
8. **Авто-обновление.** WorkManager: подбор раз в 6 часов (или по кнопке), с уведомлением о результате.
   Если текущая конфигурация перестала ходить — новый лучший конфиг можно одним тапом отправить
   в Amnezia либо применить во встроенном туннеле.

## Два режима сборки

| Flavor | Что внутри | Для кого |
|---|---|---|
| `scout` | скан + подбор + генерация + передача в AmneziaVPN | всем, кто уже пользуется amneziaVPN: тут нет VpnService, ничего не надо разрешать |
| `tunnel` | то же + собственный туннель (`VpnService` + data plane из ядра) | тех, кто хочет «нажал — работает», и для проверки доступности **из-под** туннеля |

Встроенный туннель реализован на том же коде, что и сканер (`DataPlane`: handshake, transport-пакеты,
keepalive, счётчики), поэтому «проверено» и «работает» — одна и та же реализация, а не две разные.

## Сборка

Требования: JDK 17, Android SDK (compileSdk 35, minSdk 26), Gradle не нужен — есть wrapper.

```bash
./gradlew :app:assembleScoutDebug          # APK без туннеля
./gradlew :app:assembleTunnelDebug          # APK со встроенным туннелем
adb install -r app/build/outputs/apk/tunnel/debug/app-tunnel-debug.apk
```

Релизная сборка (`assembleScoutRelease`) включает R8 и ищет `app/release.keystore`; без него
подпись берётся debug-ключом. Переменные `WARPSCOUT_STOREPASS`, `WARPSCOUT_KEYALIAS`,
`WARPSCOUT_KEYPASS`.

В Android Studio — открыть корень проекта, выбрать вариант сборки `scoutDebug` / `tunnelDebug`.

### Как пользоваться

1. Убедиться, что включены нужные профили шума (по умолчанию включены все) и выбран DNS.
2. «Подобрать конфигурацию». Первый запуск — 120 точек, ~1–2 минуты.
3. Кнопка «Импорт в Amnezia» копирует конфиг в буфер и открывает «Поделиться» с подсказкой.
   В AmneziaVPN: добавить соединение → `WireGuard` / импорт из файла — и вставить.
   (Пункт меню в Amnezia менялся между версиями; если импорт из буфера не ищется — сохраните
   `.conf` кнопкой «Сохранить» и импортируйте файл.)
4. «Авто-обновление раз в 6 ч» — включить, если не хочется помнить про это вручную.
5. Во flavor'е `tunnel` появляется кнопка «Туннель»: приложение поднимает его само
   (на первый запуск система спросит разрешение).

## Тесты

```bash
./gradlew :cli:selftest                                            # 112 проверок офлайн
python3 tools/fake_warp_endpoint.py --test-key --port 34575 &    # независимый WG-сервер
./gradlew :cli:run --args="selftest --integration 127.0.0.1:34575"   # +6 проверок = 118
./gradlew :cli:run --args="selftest --live"                        # реальные endpoint'ы (нужен UDP-выход)
python3 tools/android_stub_check.py                               # ресурсы + офлайн-компиляция app-слоя
```

Что именно проверяется — важно, потому что «компилируется» ≠ «работает»:

* **Криптография против независимых реализаций.** BLAKE2s — по векторам CPython `hashlib`;
  X25519 — RFC 7748 §6.1 и сверка с OpenSSL; XChaCha20-Poly1305 — Appendix A.1 из
  draft-irtf-cfrg-xchacha. Плюс loopback-тест: две стороны обмениваются настоящими пакетами.
* **Протокол WireGuard/AWG против ядра Linux.** Разбор handshake, cookie-цикл (mac1/mac2),
  transport-пакеты, replay-защита, keepalive — по исходникам `drivers/net/wireguard`
  (копии лежат в `docs/vendor-reference/`: `noise.c`, `send.c`, `recv.c`, `cookie.c`, `messages.h`).
* **Интеграция.** `tools/fake_warp_endpoint.py` — независимая реализация серверной части на Python
  (`cryptography`, ничего общего с нашим Kotlin): принимает инициацию, шлёт cookie reply, поднимает
  сессию, шифрует эхо. Проверка считается пройденной, только если наш клиент дошёл до
  `HANDSHAKE_RESPONSE`, а 48-байтовый IP-пакет, поданный в `tun`, вернулся обратно.
* **Android-слой.** Полноценная сборка APK требует SDK, поэтому в CI (и в `android_stub_check.py`)
  есть отдельная проверка: разбор всех XML, поиск дубликатов и висячих ссылок ресурсов,
  соответствие `getString` форматным строкам (неверная арность — это падение на устройстве, а не
  предупреждение компилятора), допустимость `foregroundServiceType`, и компиляция всего кода
  приложения против настоящего `android.jar` и jar'ов androidx/material (заглушки `R` и binding'а
  генерируются из фактической разметки, так что несовпадение типа view с тегом в XML — ошибка сборки).

CI (`.github/workflows/android.yml`): `:cli:selftest`, интеграция с фейковым эндпоинтом, затем
сборка обоих debug APK с загрузкой артефактов.

## Как считается балл

Вердикты упорядочены по силе (не по ordinal, а по `rank`; ошибка в порядке стоила мне целого
дня отладки, поэтому проверяется отдельно):

| Вердикт | Смысл | Вес |
|---|---|---|
| `HANDSHAKE_RESPONSE` → `HANDSHAKE_OK` | AEAD-тег ответа сошёлся и mac1 верен: пир держит нужный приватный ключ и принял наш статический ключ. Это 100 % рабочий endpoint | **1000** |
| `COOKIE_REPLY` | сервер живой, но под нагрузкой (или требует cookie). Тоже рабочий, просто дольше поднимается | 700 |
| `TLS_OK` | MASQUE/HTTP-порт отвечает по TLS — годится для WireGuard-over-HTTP3, для UDP-туннеля нет | 600 |
| `UDP_SILENT` | пакет ушёл, ответа нет: фильтр или мёртвый хост | 60 |
| `UDP_CLOSED` | ICMP port unreachable — порт точно закрыт | −500 |
| `DNS_FAIL` | имя не разрешилось (отдельно проверяется `DnsInspector`, чтобы не перепутать отравление DNS с блокировкой IP) | −800 |

Сверху: `+150` если шумовые пакеты не помешали handshake, `−150` если профиль шума был зарезан,
бонусы за RTT/стабильность/джиттер по полосам (`latencyBands`, `stableBands`, `jitterBands`) и
`+60` за каждый доступный ресурс. Итоговый балл и его составляющие видны в отчёте.

## Структура

```
core/   чистое ядро (JVM, без Android): crypto, wg, junk, net, keys, config, presets, tune, report,
        tunnel/DataPlane (пересылка), test/SelfCheck.kt  — 22 файла
cli/    десктопная версия ядра: selftest | tune | scan | gen | parse
app/    Android: UI (один экран), Engine, KeyVault (AndroidKeyStore), Prefs, ConfigFiles,
        Schedule + TuneWorker (WorkManager), TunnelController;
        app/src/tunnel/ — VpnService + WarpVpnService (только во flavor'е tunnel)
tools/  fake_warp_endpoint.py (независимый WG-сервер), android_stub_check.py, gen_templates.py
docs/   vendor-reference/ — копии спецификаций и исходников, по которым написан протокольный слой
samples/примеры .conf (AWG 1/2/3) с вырезанными ключами
```

`core` не знает про Android — отсюда и возможность прогнать большой перебор (5000 точек, 100
потоков) на ноутбуке через `:cli:run --args="tune ..."`, а результат забрать на телефон.

## Ограничения — честно

* **Проверено на железке только частично.** В песочнице, где писался код, UDP-исходящие пакеты не
  проходят, поэтому реальные endpoint'ы Cloudflare отсюда не видны: протокольный слой сверен с
  ядром Linux и независимым Python-сервером, а «живой» скан надо прогнать на устройстве
  (`selftest --live` или просто кнопка подбора). Если у вас что-то из этого поведёт себя иначе —
  заведите issue, приложив отчёт (он машиночитаемый, `json`).
* **APK здесь не собирались.** Сборки `assembleScoutDebug`/`assembleTunnelDebug` — задача GitHub
  Actions; локально в песочнице нет Android SDK. Композиция приложения проверена компиляцией
  против настоящего `android.jar` (см. выше), но не линковкой/упаковкой.
* **MASQUE во встроенном туннеле не работает.** `DataPlane` умеет только UDP-транспорт AWG; для
  MASQUE-endpoint'ов приложение проверяет доступность (TLS) и предлагает их как конфиг для Amnezia,
  но свой туннель поднимает по UDP-точкам. Причина простая: WireGuard-over-HTTP3 (CONNECT-UDP) —
  это отдельная большая реализация.
* **Публичные ключи = публичные ключи.** Генератор выдаёт пару «приватный ключ + peer» всем;
  это нормальная модель для WARP (трафик идёт на общий аккаунт), но не рассчитывайте на
  конфиденциальность от «своего» ключа. Приватный ключ приложения хранит в AndroidKeyStore,
  наружу не отправляет и отдаёт только в вашем же `*.conf` по вашей кнопке.
* **Юридическое.** Обход блокировок в вашей юрисдикции может быть ограничен; использование WARP
  подпадает под ToS Cloudflare. Проект исследовательский, без какой-либо гарантии.
